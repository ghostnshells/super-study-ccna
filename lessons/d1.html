Foundations: OSI and TCP/IP models

This section is not a numbered exam topic, but every other topic leans on it. The exam assumes you can name the layer a device or protocol works at, know what each PDU is called, read an Ethernet frame, and explain exactly what a host does before it sends its first packet.

Layers and PDUs

The OSI model has seven layers. The TCP/IP model (the one actually implemented) has four in RFC 1122 terms: Application, Transport, Internet and Link. Cisco material often uses a five-layer "updated TCP/IP" view that splits Link into Data link and Physical, so you will see "Layer 2" and "Layer 3" used even when someone is talking about TCP/IP. Layer numbers in Cisco speak always mean the OSI numbers.

Encapsulation and de-encapsulation

Sending host: the application produces data, TCP or UDP adds a header with source and destination ports (segment), IP adds a header with source and destination IP addresses (packet), Ethernet adds a header with MAC addresses and a trailer with the FCS (frame), and the NIC transmits bits. The receiver reverses the process, each layer reading its own header and handing the payload up (de-encapsulation). Each layer talks to the same layer on the peer (same-layer interaction) and uses the services of the layer below (adjacent-layer interaction).

Key consequence for troubleshooting: as a packet crosses routers, the IP addresses stay the same end to end (ignoring NAT), but the Layer 2 header is rebuilt on every hop. A router strips the incoming frame, makes a routing decision on the IP header, decrements TTL, and builds a new frame for the outgoing link with its own MAC as the source.

Size limits: minimum frame 64 bytes, maximum 1518 bytes untagged or 1522 with an 802.1Q tag. Anything smaller with a bad FCS is a runt; anything larger (and not a configured jumbo frame) is a giant. You will see both counters in 1.4.

MAC addresses

A MAC address is 48 bits (12 hex digits). Cisco IOS writes it as three dotted groups (0011.2233.4455); Windows uses dashes, Linux and macOS colons. The first 24 bits are the OUI (Organizationally Unique Identifier) assigned by the IEEE to the vendor; the last 24 bits are assigned by the vendor. The burned-in address (BIA) is the one in the hardware; IOS shows both "address" and "bia" in show interfaces.

  • Unicast: identifies one interface. The least significant bit of the first byte (the I/G bit) is 0.
  • Broadcast: FFFF.FFFF.FFFF. Every device in the broadcast domain processes it; switches flood it out all ports in the VLAN except the one it came in on.
  • Multicast: I/G bit is 1. IPv4 multicast maps to 0100.5Exx.xxxx, IPv6 multicast to 3333.xxxx.xxxx. Switches flood multicast by default unless IGMP snooping constrains it.

The second-least-significant bit of the first byte is the U/L bit (universal vs locally administered). It matters again when you study modified EUI-64 in 1.9.

ARP

ARP (EtherType 0x0806) maps a known IPv4 address to an unknown MAC address on the local segment. The ARP request is a broadcast ("who has 192.168.10.1? tell 192.168.10.11"), and it carries the sender's IP and MAC, so the target learns the sender's mapping too. The ARP reply is unicast back to the requester. Results go into the ARP cache: arp -a on Windows, ip neigh on Linux, show ip arp on IOS. The default ARP cache timeout on a Cisco interface is 4 hours (you can see "ARP Timeout 04:00:00" in show interfaces). IPv6 does not use ARP; it uses NDP (covered in Domain 1, 1.8 to 1.9).

Two variants worth recognizing: a gratuitous ARP is an unsolicited ARP announcing your own mapping (used after an address change or by first-hop redundancy protocols), and proxy ARP is a router answering an ARP for an address that is actually on another subnet (enabled by default on Cisco router interfaces, rarely relied on today).

Local or remote: how a host picks the next hop

Before sending an IPv4 packet, a host compares the destination with its own subnet. It applies its own subnet mask to its own address and to the destination address; if the two network portions match, the destination is local.

  1. Local destination: the host ARPs for the destination IP and sends the frame directly to the destination MAC.
  2. Remote destination: the host ARPs for its default gateway IP and sends the frame to the gateway's MAC. The IP header still carries the final destination IP. The router then repeats the same logic on its own outgoing interface.

Worked example: PC1 is 192.168.10.11/24 with gateway 192.168.10.1. To reach 192.168.10.12, it ARPs for .12 directly. To reach 192.168.20.10, it sees that 192.168.20.0 is not its network, so it ARPs for 192.168.10.1 and sends the frame with destination MAC = R1's G0/0 MAC, destination IP = 192.168.20.10.

Exam trap: A host with a wrong or missing default gateway can still reach every device in its own subnet. If "same subnet works, other subnets fail", check the gateway first. If a host's mask is wrong, it may treat a remote address as local (and ARP for it, failing) or a local address as remote.

1.1 Role and function of network components

The exam verb here is "explain": expect scenario questions such as "which device separates broadcast domains", "which device inspects application-layer traffic", or "which component manages lightweight APs". Know what each box does, at which layer, and how it is typically deployed.

1.1.a Routers

A router is a Layer 3 device that forwards packets between different IP networks using a routing table. For every packet it looks up the destination IP, picks the longest-prefix match, decrements TTL, rewrites the Layer 2 header for the outgoing interface, and forwards it. Routes come from connected interfaces, static configuration, or dynamic protocols such as OSPF (Domain 3).

  • Each router interface is its own subnet and its own broadcast domain. Routers do not forward broadcasts by default. (A DHCP relay configured with ip helper-address is the common exception: it converts specific broadcasts into unicasts.)
  • Routers connect LANs to WANs and to the internet, so they also commonly run NAT, ACLs, DHCP, VPNs and QoS.
  • Cisco enterprise routers today are the ISR 1000/4000 and Catalyst 8000 families running IOS XE. Router interfaces are administratively down by default (unlike switch ports), so each one needs no shutdown.

1.1.b Layer 2 and Layer 3 switches

A Layer 2 switch forwards Ethernet frames based on destination MAC address. It learns source MACs into its MAC address table, forwards known unicasts out one port, and floods broadcasts, multicasts (by default) and unknown unicasts out every other port in the same VLAN (the mechanics are 1.13). Forwarding is done in hardware (ASICs), so it is fast and the port count is high.

  • Each switch port is a separate collision domain, and with full duplex there are no collisions at all.
  • All ports in the same VLAN form one broadcast domain. A plain L2 switch does not separate broadcast domains; VLANs do, and a router or L3 switch is needed to move traffic between them.
  • L2 switches run VLANs, 802.1Q trunking, STP and EtherChannel (Domain 2). A management IP lives on an SVI (for example interface vlan 1) and the switch uses ip default-gateway to reach other subnets.

A Layer 3 switch (multilayer switch) does everything an L2 switch does and also routes between VLANs in hardware. It has two kinds of Layer 3 interface: SVIs (interface vlan 10, the gateway for a VLAN) and routed ports (a physical port converted with no switchport). Routing between interfaces requires the global command ip routing; it is disabled by default on many Catalyst models, so the CCNA expects you to configure it (check with show running-config | include ip routing). L3 switches typically have far more Ethernet ports and higher forwarding rates than routers, but fewer WAN interface types and features, so the usual design is L3 switches inside the campus and routers at the WAN or internet edge.

Exam trap: "Which device separates broadcast domains?" The answer is a router or a Layer 3 interface (SVI or routed port), not a Layer 2 switch. "Which device separates collision domains?" Switches (each port) and routers. Hubs separate neither.

1.1.c Next-generation firewalls and IPS

A firewall enforces policy between security zones, typically inside (trusted), outside (internet) and a DMZ (public-facing servers). Modern firewalls are stateful: when an inside host opens a session, the firewall records it in a state table (addresses, ports, protocol, TCP state) and automatically permits the return traffic, while unsolicited traffic from outside is denied unless a rule explicitly allows it. A stateless packet filter (like a basic ACL) checks each packet alone and needs explicit rules for return traffic.

A traditional stateful firewall decides based on Layer 3 and 4 information: IP addresses, protocol and ports. A next-generation firewall (NGFW) keeps stateful filtering and adds deeper inspection:

  • Application visibility and control: identifies the actual application (for example, a specific file-sharing app) regardless of the port it uses, and allows or blocks by application.
  • Integrated IPS: inspects payloads for known exploit signatures and anomalies, inline.
  • URL filtering: permits or blocks web access by URL category and reputation.
  • Advanced malware protection: file reputation, sandboxing and retrospective analysis.
  • Identity awareness and threat intelligence: rules by user or group, and continuously updated threat feeds (Cisco Talos for Cisco Secure Firewall).

Cisco's current product line is Cisco Secure Firewall (formerly Firepower), running Firewall Threat Defense; older Cisco ASAs are traditional stateful firewalls that can also run NGFW services.

IDS vs IPS. An IDS (intrusion detection system) receives a copy of traffic (from a SPAN port or tap), so it sits out of band: it can detect and alert but cannot stop the original packet. An IPS (intrusion prevention system) sits inline, so traffic passes through it and it can drop malicious packets in real time. The trade-off: an inline IPS adds latency and is a point of failure (configured to fail open or fail closed), and a false positive blocks legitimate traffic. Both use signature-based detection (match known patterns, needs updates) and anomaly or behavior-based detection (flag deviation from a baseline, can catch new attacks but produces more false positives).

1.1.d Access points

An access point (AP) is the Layer 2 bridge between the 802.11 wireless medium and the 802.3 wired network. It advertises one or more SSIDs, associates and authenticates clients, and converts frames between 802.11 and Ethernet formats. An AP creates a BSS (basic service set) identified by its BSSID (a radio MAC address). Wireless is a shared, half-duplex medium that uses CSMA/CA, not CSMA/CD.

  • Autonomous AP: configured individually, handles everything itself; switch port is usually a trunk if it serves several VLANs.
  • Lightweight AP (LAP): works with a WLC using CAPWAP. Real-time functions (beacons, probe responses, ACKs, encryption) stay on the AP; management functions (authentication, roaming, RF management, config) move to the WLC. This split is called split-MAC. In the default local mode, the switch port is an access port.
  • Cloud-managed AP: managed from a cloud dashboard (Cisco Meraki).

APs are commonly powered by PoE from the access switch. Architectures and AP modes are covered in 2.6 and 2.7.

1.1.e Controllers: WLC and Catalyst Center

Wireless LAN controller (WLC). Centrally manages lightweight APs. Each AP builds a CAPWAP tunnel to the WLC: UDP 5246 for control (encrypted with DTLS) and UDP 5247 for data. The WLC pushes config to APs, handles client authentication (often with RADIUS), coordinates roaming, and runs Radio Resource Management (automatic channel and power assignment). Cisco WLCs today are the Catalyst 9800 family (IOS XE), including the 9800-CL virtual controller and an embedded controller that runs on an AP; the older AireOS controllers (such as the 3504 and 5520) are what many GUI screenshots in study material show.

Cisco Catalyst Center (formerly Cisco DNA Center). Cisco renamed DNA Center to Catalyst Center in 2023. The v1.1 exam topics just say "Controllers" (v1.0 named "Cisco DNA Center and WLC"), so expect either product name in questions and study material. It is the enterprise campus SDN controller and management platform: you express intent in a GUI or through its northbound REST APIs, and it configures devices through southbound protocols (SSH/CLI, NETCONF, SNMP). Its main jobs:

  • Automation and provisioning: device discovery, Plug and Play zero-touch onboarding, templates, software image management.
  • Assurance: health scores, telemetry, AI-driven analytics for clients, devices and applications.
  • Policy and SD-Access: builds and manages the SD-Access fabric.

It runs as a physical appliance on-premises or as a virtual appliance. Controller-based networking and the planes (control, data, management) are Domain 6 material; for 1.1 know what each controller manages.

Exam trap: A WLC manages APs (wireless). Catalyst Center manages the whole campus (switches, routers, WLCs, APs). Do not confuse "controller" in a wireless question with Catalyst Center.

1.1.f Endpoints

Endpoints are the devices at the edge that originate and consume traffic: PCs and laptops, phones and tablets, IP phones, printers, cameras, badge readers, IoT sensors and industrial devices. Each needs an IP address, mask, default gateway and DNS server (statically or via DHCP). From a security view the endpoint is the most common entry point for attacks, which is why access-layer features such as port security, 802.1X and DHCP snooping (Domain 5) exist. In a regulated lab environment, endpoints are often instrument PCs that cannot be patched freely, which is a strong reason to segment them into their own VLAN behind a firewall.

1.1.g Servers

A server provides a service to clients: web, file, email, DNS, DHCP, authentication (Active Directory, RADIUS), databases, applications. In the client-server model, clients initiate requests to a server listening on a known port; in peer-to-peer, each device can act as both. Servers usually live in a data center or server VLAN (or in the cloud), are frequently virtual machines on a hypervisor (1.12), and are often dual-homed to two switches with NIC teaming for redundancy. Servers connect to access or leaf switches, never to spine switches in a spine-leaf design.

1.1.h Power over Ethernet (PoE)

PoE delivers DC power and data over the same twisted-pair cable, so APs, IP phones and cameras need no local power outlet. The switch (or a midspan injector) is the PSE (power sourcing equipment); the device receiving power is the PD (powered device).

How the PSE decides to power a port. The PSE never just pushes voltage. It first performs detection (applies a low voltage and looks for the PD's signature resistance), then classification (the PD indicates its class so the PSE knows the maximum power to budget), then applies power and monitors it. A non-PoE device fails detection and gets data only. After power-up, Cisco devices can fine-tune the amount with CDP, and standards-based devices with LLDP (LLDP-MED / Power via MDI TLVs).

1.2 Network topology architectures

The exam verb is "describe characteristics". You will not design a network, but you must recognize each architecture from a diagram or description, know what each layer or tier does, and know why one is chosen over another.

Two terms recur. A star topology has one central device with links to each other device (an access switch and its endpoints). A full mesh connects every node to every other node; a partial mesh has some but not all of those links. Campus designs use a star from each access switch up to distribution, and full or partial mesh between distribution and core.

1.2.a Two-tier (collapsed core)

A two-tier campus has an access layer and a distribution layer, where the distribution switches also perform the core function. Hence "collapsed core": core and distribution live in the same pair of switches.

  • Every access switch uplinks to both distribution/core switches (two uplinks per access switch for redundancy). The access switch is the hub of a star for its endpoints.
  • The distribution pair is usually Layer 3 switches: they are the default gateways for the access VLANs, route between VLANs, connect to the WAN/internet edge, and are linked to each other.
  • Suits a single building or small campus. It saves the cost of a separate core layer.

The problem it does not solve: as you add buildings, each with its own distribution pair, connecting every distribution pair to every other one needs a growing number of links (a full mesh grows as n(n-1)/2). That is when a core layer is added.

1.2.b Three-tier

The three-tier campus inserts a core layer above several distribution blocks. Each distribution pair connects to the core, and the core connects everything to everything.

Exam trap: Endpoints connect to the access layer, never to the core. Questions sometimes describe "a layer that provides high-speed backbone connectivity and should avoid packet manipulation": that is the core. "Aggregates access switches and provides the L2/L3 boundary": distribution.

1.2.c Spine-leaf

Spine-leaf is the modern data center fabric (Cisco ACI and Nexus VXLAN EVPN fabrics use it). It replaced three-tier data center designs because virtualization and distributed applications created heavy east-west traffic (server to server) instead of mostly north-south traffic.

  • Every leaf connects to every spine.
  • Leaves do not connect to other leaves, and spines do not connect to other spines.
  • All endpoints (servers, storage, firewalls, routers to the WAN, the ACI APIC controllers) connect to leaves. Nothing but leaves connects to spines. A leaf that connects to external networks is often called a border leaf.
  • Any server reaches any server on another leaf in the same number of hops: leaf, spine, leaf. That gives consistent, predictable latency.
  • All spine paths are equal cost, so traffic is load-balanced across them (ECMP). Links are Layer 3 (or an overlay such as VXLAN), not STP-blocked Layer 2.
  • Scale out: add a leaf for more server ports (connect it to every spine); add a spine for more bandwidth between leaves (connect it to every leaf). Link count = spines times leaves.

Remember: Spine-leaf rules: leaf-to-every-spine, no leaf-leaf, no spine-spine, endpoints only on leaves, equal hop count between any two leaves.

1.2.d WAN

A WAN connects sites over distances the enterprise does not own the cabling for, so it uses a service provider. Know these options and their characteristics.

Leased line
A dedicated point-to-point circuit between two sites (historically T1 at 1.544 Mbps or E1 at 2.048 Mbps, delivered to a serial interface with HDLC or PPP, using a CSU/DSU). Private, fixed bandwidth, predictable, but expensive and only connects two sites.
MPLS VPN
The provider runs an MPLS network and gives each customer a private Layer 3 VPN. Customer Edge (CE) routers connect to Provider Edge (PE) routers; the provider's core (P) routers forward on labels. Any-to-any connectivity between sites, the provider participates in routing (the CE exchanges routes with the PE), supports QoS, and accepts many access types (Ethernet, DSL, wireless). A Layer 2 MPLS VPN (VPLS) variant also exists.
Metro Ethernet (Carrier Ethernet)
The provider delivers an Ethernet handoff (a fiber or copper Ethernet port) and carries frames across its network. MEF service types: E-Line (point-to-point), E-LAN (any-to-any, like one big switch), E-Tree (hub-and-spoke, rooted multipoint). Familiar Ethernet interfaces, easy bandwidth upgrades, but limited to a metro area or provider footprint.
Internet VPN
Use cheap internet access and build encrypted tunnels across it. Site-to-site IPsec VPN connects two networks (the routers or firewalls do the encryption, the hosts are unaware); remote-access VPN connects one user's device with a client (Cisco Secure Client, TLS or IPsec). GRE over IPsec adds multicast and routing protocol support. No provider SLA across the internet.
Broadband internet access
DSL (over telephone lines, with a DSL modem; asymmetric), cable (over the cable TV coax network, DOCSIS, cable modem), fiber (FTTH/FTTP, often with a GPON optical network terminal), and satellite. Typically used with an internet VPN for enterprise use.
4G/5G cellular
Wireless WAN through a mobile carrier. Used for small or temporary sites, mobile sites, and very often as a backup link for a branch.

Software-defined WAN (Cisco Catalyst SD-WAN) combines several of these transports under centralized control; it belongs to Domain 6.

WAN topologies

  • Point-to-point: one link between two sites (leased line, E-Line).
  • Hub-and-spoke: branches connect to a central hub (usually HQ or data center). Cheapest and simplest, but branch-to-branch traffic goes through the hub and the hub is a single point of failure unless it is redundant.
  • Full mesh: every site directly connected to every other. Best redundancy and direct paths, but N(N-1)/2 links: 10 sites need 45.
  • Partial mesh: only the important sites get direct links; a cost compromise.

1.2.e Small office/home office (SOHO)

A SOHO network serves a handful of users. Instead of separate devices it uses one integrated box, usually called a "wireless router", that combines:

  • a router with one WAN port toward the ISP's modem or ONT (cable, DSL or fiber) and the LAN side as the default gateway;
  • a small switch (typically four LAN ports);
  • a wireless AP (autonomous, configured on the box itself);
  • a basic stateful firewall;
  • DHCP server for the LAN and NAT/PAT so all inside hosts share the single public address from the ISP.

Sometimes the ISP's modem is built into the same box. A larger home or small office may add a separate PoE switch or mesh APs, but the design stays flat (usually one subnet).

1.2.f On-premises and cloud

On-premises means the organization owns and operates the servers, storage and network in its own facility or a colocation space. It buys hardware up front (capital expense), sizes for peak load, and has full control and full responsibility (patching, power, cooling, physical security). This is common where data residency, latency to plant equipment, or validation requirements matter.

Cloud computing, as defined by NIST SP 800-145, has five essential characteristics:

  1. On-demand self-service: the consumer provisions resources without a human at the provider (a web portal or API).
  2. Broad network access: available over the network from many client types.
  3. Resource pooling: the provider serves many tenants from shared physical resources (multitenancy), with location abstracted.
  4. Rapid elasticity: scale up and down quickly, often automatically; capacity appears unlimited.
  5. Measured service: usage is metered and billed (operating expense).

Connecting an enterprise to a public cloud

  • Internet: simplest, cheapest; no SLA end to end and security relies on TLS.
  • Internet VPN: site-to-site IPsec tunnel from the enterprise edge to the cloud provider's VPN gateway; encrypted, still internet quality.
  • Private WAN: extend the MPLS VPN or Metro Ethernet service to the cloud provider, or use a dedicated private connection product (for example AWS Direct Connect or Azure ExpressRoute) through a colocation exchange. Predictable performance and no internet exposure, at a higher cost and longer lead time.

Trade-off summary: cloud gives speed of provisioning, elasticity and OpEx billing; on-prem gives control, predictable cost at steady load, and low latency to local systems. Many organizations run hybrid.

1.3.b Connections: shared-media Ethernet and point-to-point

Shared media. Original Ethernet (10BASE5, 10BASE2 coax) and later hubs put every device on one shared medium. A hub is a Layer 1 repeater: a signal in one port is regenerated out every other port. Only one device can transmit successfully at a time, so the whole hub (and every hub connected to it) is one collision domain and every device must run half duplex.

Half-duplex Ethernet uses CSMA/CD (carrier sense multiple access with collision detection):

  1. Listen: if the medium is busy, wait (carrier sense).
  2. When idle, transmit.
  3. While transmitting, listen for a collision. If one occurs, send a jam signal so every station notices.
  4. Each station waits a random backoff time and tries again.

Collisions are normal in half duplex. A legal collision must happen within the first 64 bytes (512 bit times) of a frame; one that happens later is a late collision, which signals a problem (duplex mismatch or a segment that is too long).

Point-to-point. A switch port connected to one device forms a point-to-point link with only two devices. With separate transmit and receive pairs, both can send at the same time: full duplex. In full duplex, CSMA/CD is disabled and collisions cannot occur. This is the normal state of every modern switched link, and also of WAN links such as serial leased lines and Metro Ethernet E-Line. Full duplex also doubles effective capacity (a 1 Gbps full-duplex link carries 1 Gbps each way).

Wireless is shared media again: an 802.11 channel is half duplex and uses CSMA/CA (collision avoidance), because radios cannot detect a collision while transmitting.

Remember: Rising CRC and runts on one end, rising late collisions on the other end = duplex mismatch. Steady CRC errors with no collisions on a full-duplex link = physical layer (cable, connector, interference, bad optic). Output drops = congestion, not a cable problem.

Speed and duplex autonegotiation

Ethernet autonegotiation (IEEE 802.3, clause 28 for BASE-T) lets the two ends exchange their capabilities using fast link pulses and choose the best common speed and duplex: fastest speed first, and full duplex in preference to half. Cisco switch ports default to speed auto and duplex auto. Configuring both speed and duplex manually disables autonegotiation on that port.

When one side is hardcoded (autonegotiation off) and the other side is auto, the auto side hears no negotiation messages, so:

  • Speed: it can still sense the speed from the electrical signal (parallel detection), so speed normally matches. If that fails, it uses the slowest supported speed (10 Mbps).
  • Duplex: it cannot sense duplex. It uses the IEEE default: half duplex at 10 or 100 Mbps, full duplex at 1000 Mbps and above.

So the classic duplex mismatch: one side hardcoded to speed 100 and duplex full, the other side left on auto. The auto side settles on 100/half. The link comes up and passes traffic, but performance is poor and gets worse under load.

Why a duplex mismatch produces that counter pattern. The full-duplex side transmits whenever it wants. The half-duplex side, seeing the other side transmit while it is sending, treats it as a collision, stops, and jams. If that happens after its first 64 bytes, it counts a late collision. Meanwhile the full-duplex side receives the half-duplex side's truncated frames and jam signals as runts and CRC/FCS errors. Cisco devices running CDP also log the mismatch:

Other cable and physical-layer problems

  • Cable longer than 100 m: signal attenuation causes CRC errors; on half duplex, late collisions too.
  • Damaged or poorly terminated cable, untwisted pairs at the connector, EMI from power cables or fluorescent ballasts: CRC and input errors with no collisions. Cable of too low a category for the speed (for example Cat 3 on a 100 Mbps or gigabit link, or Cat 6 on a 10GBASE-T run longer than about 55 m) can do the same.
  • Wrong cable type (without Auto-MDIX): link stays down/down.
  • Fiber: dirty connectors, tight bends, mismatched optics (SX to LX, or multimode optic on single-mode fiber), or Tx/Rx strands swapped: link down or CRC errors. show interfaces transceiver shows optical receive and transmit power on DOM-capable optics.

Both are Layer 4 protocols that add port numbers so many applications on one host can share the network (multiplexing). A connection is identified by the 5-tuple: source IP, destination IP, protocol, source port, destination port. Everything else differs.

Connection establishment: the 3-way handshake

  1. SYN: the client sends SYN with its ISN (seq=1000). It is now in SYN-SENT.
  2. SYN-ACK: the server, which was in LISTEN on the port, replies with SYN and ACK set: its own ISN (seq=5000) and ack=1001 (the SYN consumed one number).
  3. ACK: the client sends ACK with ack=5001. Both sides are ESTABLISHED. The handshake also exchanges options such as MSS (maximum segment size) and window scaling.

If nothing listens on the port, the server answers the SYN with a RST (a "connection refused" on the client). A firewall that silently drops the SYN causes a client timeout instead, which is a useful troubleshooting distinction.

Data transfer: sequence numbers, acknowledgments, retransmission

After the handshake, the client sends 500 bytes with seq=1001. The server replies ack=1501: "I have everything up to byte 1500, send 1501 next." If a segment is lost, the receiver keeps acknowledging the last in-order byte. The sender retransmits when its retransmission timer (RTO) expires without an ACK, or earlier when it receives three duplicate ACKs (fast retransmit). The receiver uses sequence numbers to reorder segments and discard duplicates, so the application always gets an in-order byte stream.

Note that Wireshark shows relative sequence numbers by default (the ISN is displayed as 0), which makes the arithmetic easy to follow.

Windowing and flow control

TCP does not wait for an ACK after every segment. The receiver advertises a window size, and the sender may have up to that many unacknowledged bytes in flight. As ACKs arrive the window slides forward, hence sliding window. Flow control is the receiver protecting itself: if its buffer fills, it advertises a smaller window, or a window of 0 to pause the sender. On a healthy connection the effective window grows, which raises throughput; when loss occurs, TCP's congestion control (slow start, congestion avoidance) cuts its sending rate and then ramps up again. For the exam: windowing = flow control, a larger window = more data before an ACK = better throughput, and the receiver controls the advertised window.

Connection termination: the 4-way close

  1. The side that finishes first (active closer) sends FIN (FIN-WAIT-1).
  2. The other side ACKs it (the closer moves to FIN-WAIT-2; the other side is in CLOSE-WAIT and may still send data).
  3. When the other side is done, it sends its own FIN (LAST-ACK).
  4. The active closer ACKs it and waits in TIME-WAIT for 2 x MSL before fully closing, so a lost final ACK can be resent and stray old segments die out.

Steps 2 and 3 are often combined into one FIN-ACK segment, so captures frequently show three segments. A RST tears a connection down immediately with no handshake.

Why UDP

UDP is the right choice when retransmitting late data is worse than losing it, when the exchange is a single request and reply, or when the application provides its own reliability:

  • Voice and video (RTP over UDP): a retransmitted voice sample arrives too late to play. Cisco voice uses even UDP ports in the 16384 to 32767 range for RTP. Real-time traffic prefers low delay and jitter over completeness.
  • DNS queries: one small question, one small answer; the resolver simply retries. DNS uses TCP 53 for zone transfers and for responses too large for UDP.
  • DHCP: the client has no IP address yet and must broadcast, which TCP cannot do.
  • TFTP: simple file transfer that adds its own lock-step acknowledgments (each block is ACKed) on top of UDP.
  • SNMP, syslog, NTP: small, frequent, low-overhead messages; NTP also needs low, consistent latency.

Exam trap: "Reliable" in exam questions means TCP's acknowledgment and retransmission, not "works well". TFTP is reliable at the application layer but still uses UDP. Also: TCP is the one with windowing and sequencing; UDP has neither, and its header has only four fields.

1.6 Configure and verify IPv4 addressing and subnetting

Subnetting is the single most reused skill on the CCNA. It shows up directly (find the subnet, pick a mask) and indirectly in routing tables, ACL wildcards, OSPF network statements, NAT pools and troubleshooting questions where one host has the wrong mask. The goal for this week is not just to get the right answer, but to get it in under 30 seconds without writing binary.

Classful background (still tested)

Before CIDR (1993), the first bits of an address fixed its class and therefore its default mask. Routing is classless today, but the exam still expects you to recognize the class of an address and its default mask, and older terms like "Class C network" still appear in question stems.

Masks: prefix length vs dotted decimal

A subnet mask is 32 bits: a run of 1s (the network part, including any borrowed subnet bits) followed by 0s (the host part). The prefix length (/n) is just the count of 1s. IOS interface commands take dotted decimal (ip address 10.1.1.1 255.255.255.0); most show commands display the prefix (10.1.1.0/24). You must convert both ways instantly.

Only nine values can ever appear in a mask octet: 0, 128, 192, 224, 240, 248, 252, 254, 255. Each one adds a 1 bit from the left (128, +64, +32, +16, +8, +4, +2, +1).

Network, broadcast and usable hosts (the binary view)

Every subnet has three landmarks:

  • Network (subnet) ID: all host bits 0. Identifies the subnet in routing tables. Not assignable to a host.
  • Directed broadcast address: all host bits 1. Not assignable to a host.
  • Usable range: network + 1 through broadcast - 1.

Binary check, host 192.168.10.77/27:

Address   192.168.10.77    last octet 0100 1101
Mask      255.255.255.224  last octet 1110 0000   (27 = 24 + 3 bits)
AND       network          last octet 0100 0000 = 64   -> 192.168.10.64
Host bits set to 1         last octet 0101 1111 = 95   -> 192.168.10.95 (broadcast)
Usable                     192.168.10.65 - 192.168.10.94  (2^5 - 2 = 30 hosts)

Binary always works, but it is slow. The block-size method below gives the same answer with mental arithmetic only.

The block-size ("magic number") method

  1. Find the interesting octet: the octet where the mask is neither 255 nor 0. For a prefix, it is octet number ceil(n/8): /20 is in octet 3, /27 in octet 4, /13 in octet 2.
  2. Compute the block size: 256 minus the mask value in that octet. (/27: 256 - 224 = 32.)
  3. The subnets start at multiples of the block size in that octet: 0, 32, 64, 96...
  4. The network ID is the largest multiple of the block size that is less than or equal to the host's value in the interesting octet. Octets to the left are copied, octets to the right become 0.
  5. The broadcast is the next network ID minus 1: in the interesting octet, network + block - 1; octets to the right become 255.
  6. First usable = network + 1 (last octet). Last usable = broadcast - 1 (last octet).

Worked example 1: find the subnet of a host (mask in the 4th octet)

Host 192.168.10.77 /27. Interesting octet: 4th. Block: 256 - 224 = 32. Multiples of 32: 0, 32, 64, 96. The largest one not above 77 is 64.

  • Network: 192.168.10.64
  • Broadcast: 64 + 32 - 1 = 95, so 192.168.10.95
  • Usable: 192.168.10.65 to 192.168.10.94 (30 hosts)

Worked example 2: mask in the 3rd octet

Host 172.16.45.200 /20 (255.255.240.0). Interesting octet: 3rd. Block: 256 - 240 = 16. Multiples of 16: 0, 16, 32, 48. The largest not above 45 is 32. The 4th octet goes to 0 for the network and 255 for the broadcast.

  • Network: 172.16.32.0
  • Next network: 172.16.48.0, so broadcast is 172.16.47.255
  • Usable: 172.16.32.1 to 172.16.47.254
  • Hosts: 12 host bits, 212 - 2 = 4,094

Exam trap: When the interesting octet is not the last one, the last usable host ends in .254 and the broadcast ends in .255, but addresses like 172.16.40.0 and 172.16.39.255 are perfectly valid hosts inside 172.16.32.0/20. Only the very first and very last address of the whole block are reserved.

Worked example 3: mask in the 2nd octet

Host 10.130.5.9 /13 (255.248.0.0). Interesting octet: 2nd. Block: 256 - 248 = 8. Multiples of 8 near 130: 128, 136. So:

  • Network: 10.128.0.0
  • Broadcast: 10.135.255.255 (next network 10.136.0.0 minus 1)
  • Usable: 10.128.0.1 to 10.135.255.254
  • Hosts: 19 host bits, 219 - 2 = 524,286

Worked example 4: is this a valid host address?

  • 192.168.5.63/26: block 64; subnets .0, .64. 63 is the last address of the .0 block, so it is the broadcast. Not assignable.
  • 10.1.1.0/23: block 2 in the 3rd octet; subnets 10.1.0.0, 10.1.2.0. The subnet is 10.1.0.0/23, range 10.1.0.1 to 10.1.1.254. So 10.1.1.0 is a valid host, even though it "looks like" a network ID.
  • 10.0.67.255/22: block 4 in the 3rd octet; subnets 10.0.64.0, 10.0.68.0. Broadcast is 10.0.67.255. Not assignable.
  • 200.1.1.200/30: block 4; 200 is a multiple of 4, so it is the network ID of 200.1.1.200/30 (hosts .201 and .202, broadcast .203). Not assignable.

Worked example 5: are two hosts in the same subnet?

PC-A 172.20.14.33/21 and its gateway 172.20.15.200/21. Block 8 in the 3rd octet: subnets 172.20.8.0 and 172.20.16.0. Both 14 and 15 fall in 8 to 15, so both are in 172.20.8.0/21 (range 172.20.8.1 to 172.20.15.254). The gateway is reachable. This is the exact check you do in troubleshooting questions where "PC cannot reach its default gateway": compute both subnets and compare.

Worked example 6: how many subnets and hosts?

  • 172.16.0.0/16 subnetted with /22: borrowed bits s = 22 - 16 = 6, so 26 = 64 subnets. Host bits h = 32 - 22 = 10, so 210 - 2 = 1,022 hosts per subnet.
  • 10.0.0.0/8 subnetted with /12: s = 4, 16 subnets; h = 20, 1,048,574 hosts each.
  • 192.168.1.0/24 subnetted with 255.255.255.240 (/28): s = 4, 16 subnets; h = 4, 14 hosts each.

VLSM design

Variable Length Subnet Masking means using different prefix lengths inside one major block, sized to each segment. Classless routing protocols (OSPF, EIGRP, RIPv2) and static routes carry the mask with each route, so VLSM works everywhere on a modern network. The method:

  1. Sort requirements from largest to smallest.
  2. Give each the smallest block that fits (2h - 2 >= hosts).
  3. Allocate from the start of the free space, largest first. Because every block size is a power of two and you go largest first, each new block automatically starts on a valid boundary.
  4. Record network, mask, first/last usable, broadcast. Give the router the first usable address (a common convention, not a rule).

/31 point-to-point links and /32 host addresses

/31 (RFC 3021). On a point-to-point link only two devices exist, so the network and broadcast addresses are pure waste. RFC 3021 lets a /31 be used on point-to-point links: both addresses are host addresses and there is no directed broadcast (limited broadcast 255.255.255.255 still works). Example: R1 10.0.0.0/31, R2 10.0.0.1/31. IOS accepts a /31 on serial and Ethernet interfaces; on Ethernet it prints a warning because Ethernet is technically multi-access:

R1(config)#interface GigabitEthernet0/0/2
R1(config-if)#ip address 10.0.0.0 255.255.255.254
% Warning: use /31 mask on non point-to-point interface cautiously
R1(config-if)#no shutdown

The configuration is accepted and works when the other end also uses /31. Both ends must use /31.

/32. A /32 identifies exactly one address. You see it as loopback interface addresses (interface Loopback0 / ip address 1.1.1.1 255.255.255.255), as host routes in static routing, and as the "L" (local) routes that IOS installs for each interface address (L 172.16.8.1/32 is directly connected).

Speed technique for exam timing

Cisco allots 120 minutes for the exam and does not publish the item count. Plan on roughly a minute per item, and less for pure subnetting questions so you bank time for simulations. Practice until a "find the subnet" question takes under 20 seconds.

  1. Memorize two rows. Mask values 128 192 224 240 248 252 254 255 and block sizes 128 64 32 16 8 4 2 1. They line up: 224 goes with 32, 248 with 8.
  2. Prefix to octet. Subtract 8 until the remainder is 1 to 8: /20 = 8 + 8 + 4, so 4 bits into the 3rd octet, mask 240, block 16. /27 = 3 full octets + 3 bits, mask 224, block 32.
  3. Floor to a multiple. Divide the host's interesting octet by the block and drop the remainder: 45 / 16 = 2 remainder 13, so 2 x 16 = 32.
  4. Broadcast = next network minus one. Never compute it independently.
  5. Hosts from prefix. Memorize 2h - 2 for h = 2 to 12: 2, 6, 14, 30, 62, 126, 254, 510, 1022, 2046, 4094.
  6. Elimination. In multiple choice, throw out any answer whose network ID is not a multiple of the block. When the mask is in the last octet (/25 to /30), a broadcast always ends in an odd number and a network ID in an even number.
  7. Write a cheat row on the erasable board at the start of the exam: the mask row, the block row and the host-count row. It takes 30 seconds and saves minutes.

Recap

  • Block size = 256 minus the mask octet; network = largest multiple of the block not above the host's octet; broadcast = next network minus 1.
  • Usable hosts = 2h - 2; subnets = 2s (subnet zero is usable).
  • Class A 1-126, B 128-191, C 192-223, D 224-239, E 240-255; 127 is loopback.
  • VLSM: allocate largest first; every block must start on a multiple of its own size; check for overlaps.
  • /31 = two usable addresses on point-to-point links (RFC 3021); /32 = single host (loopbacks, host routes, L routes).
  • Configure with ip address A.B.C.D mask + no shutdown; verify with show ip interface brief, show ip interface, show ip route connected.
  • IOS rejects overlapping subnets and network/broadcast addresses on interfaces; a wrong host mask causes partial reachability.

1.7 Private IPv4 addressing

IPv4 has about 4.3 billion addresses, far fewer than the devices that want them, and IANA handed out its last free /8 blocks to the regional registries in 2011. Two tools stretched IPv4: private address space, which anyone can reuse internally, and NAT, which lets many private hosts share a few public addresses. IPv6 (1.8) is the long-term fix.

Exam trap: 172.32.1.1 and 172.15.1.1 are public. 192.169.1.1 is public. 172.16.0.0/12 ends at 172.31.255.255 because a /12 in the second octet has a block size of 16 (16 + 16 - 1 = 31). Distractors often use 172.32 or "172.16.0.0/16" to see whether you know the real prefix.

Why NAT is needed

A packet from 10.1.1.10 can reach a web server on the Internet, but the reply addressed to 10.1.1.10 cannot be routed back, because thousands of networks use that address. NAT on the edge router rewrites the private source address to a public address (and, with PAT, a unique source port) on the way out, records the mapping, and reverses it for the reply. Terms you will meet in 4.1: inside local (the private address, such as 10.1.1.10), inside global (the public address it is translated to, such as 203.0.113.5). PAT (NAT overload) is what lets an entire site share one public address.

Private addressing has side benefits (internal address plans do not depend on the ISP, and internal hosts are not directly reachable from outside without a translation) but NAT is not a security control by itself; a firewall policy is.

1.8 Configure and verify IPv6 addressing and prefix

Address format

An IPv6 address is 128 bits, written as eight 16-bit groups (hextets) of four hex digits separated by colons, for example 2001:0db8:acad:0010:0000:0000:0000:0001. Hex is case-insensitive; RFC 5952 says to write lowercase, while IOS displays uppercase. There is no broadcast in IPv6: multicast does that job.

Abbreviation rules

  1. Drop leading zeros in any hextet: 0db8 becomes db8, 0010 becomes 10, 0000 becomes 0. Never drop trailing zeros (acd0 stays acd0).
  2. Replace one run of consecutive all-zero hextets with ::, only once per address (otherwise the length would be ambiguous).
  3. Per RFC 5952 (the canonical form): compress the longest run; if two runs tie, compress the first; do not use :: for a single zero hextet.
FullShortest correct form
2001:0db8:0000:0000:0000:ff00:0042:83292001:db8::ff00:42:8329
2001:0db8:0000:0001:0000:0000:0000:00012001:db8:0:1::1
2001:0db8:0000:0000:0001:0000:0000:00012001:db8::1:0:0:1 (two runs of two zeros tie, so compress the first)
2001:0db8:00a0:0000:0000:0bcd:0000:00002001:db8:a0::bcd:0:0
fe80:0000:0000:0000:0000:0000:0000:0001fe80::1

To expand, count the hextets you can see, and the :: stands for however many zero hextets bring the total to eight. fd12:3456:789a:1::1 shows five, so :: is three: fd12:3456:789a:0001:0000:0000:0000:0001.

Exam trap: An answer with two :: (like 2001::1::1) is always invalid. An answer that removes trailing zeros (writing 2001:db8:a:: for 2001:db8:a000::) is also wrong.

Prefixes and prefix lengths

IPv6 uses prefix-length notation only (no dotted masks). A typical global unicast address splits like this:

Prefix lengthTypical use
/32Allocation to an ISP from a regional registry (2001:db8::/32 is the documentation prefix)
/48Typical allocation to a site or enterprise; 16 bits of subnet ID
/56Common allocation to homes and small sites; 256 /64s
/64Every LAN segment. SLAAC and EUI-64 require a 64-bit interface ID, so LANs are always /64.
/127Point-to-point router links (RFC 6164): two addresses, avoids neighbor cache exhaustion attacks. /64 also works and many designs use it.
/128Single host: loopbacks, host routes, the local (L) routes in the IPv6 routing table

Finding the prefix of an address. Keep the first n bits, zero the rest. On a nibble boundary (a multiple of 4) this is just "keep the first n/4 hex digits".

  • 2001:db8:acad:1234:5678::1/64: keep 4 hextets, prefix 2001:db8:acad:1234::/64.
  • 2001:db8:abcd:12ab::1/56: keep 14 hex digits (3 hextets plus the first 2 digits of the 4th), prefix 2001:db8:abcd:1200::/56.
  • 2001:db8:abcd:12ab::1/52: keep 13 hex digits, prefix 2001:db8:abcd:1000::/52.

Subnetting a /48 into /64s just counts in the fourth hextet: 2001:db8:acad:0::/64, 2001:db8:acad:1::/64 ... 2001:db8:acad:ffff::/64. Many designs encode the VLAN in it (VLAN 10 = 2001:db8:acad:10::/64).

Address resolution. Instead of a broadcast, the NS goes to the target's solicited-node multicast group, so only hosts whose addresses share those last 24 bits even look at it. Results go into the neighbor cache (show ipv6 neighbors).

Duplicate Address Detection (DAD). Before using any new unicast address (static, SLAAC or DHCPv6), a node sends an NS for its own tentative address, with source :: (unspecified) and destination the solicited-node group of that address. If anyone answers with an NA, the address is a duplicate and is not used. On IOS a duplicate is marked [DUP] in show ipv6 interface. Anycast addresses skip DAD.

SLAAC sequence on a host: build link-local, DAD it, send RS to FF02::2, receive RA with prefix 2001:db8:acad:10::/64, build the global address (prefix + interface ID), DAD it, set the default gateway to the router's link-local address.

Common IPv6 errors

  • No ipv6 unicast-routing: interfaces have addresses and can ping neighbors, but the router does not forward IPv6, does not send RAs and does not join FF02::2. SLAAC hosts end up with only a link-local address.
  • LAN prefix not /64: SLAAC and EUI-64 need a 64-bit interface ID.
  • Typo in the prefix between router and host: host and gateway in different /64s; on-link communication fails even though both are "2001:db8:acad:...".
  • Interface shut down: show ipv6 interface brief shows [administratively down/down], and the connected routes are missing.

1.9 IPv6 address types

1.9.a Unicast: global, unique local, link-local

Global unicast (GUA), 2000::/3. The IPv6 equivalent of public IPv4 addresses: globally unique and routable. 2000::/3 means the first three bits are 001, so the first hex digit is 2 or 3. IANA allocates blocks to the regional registries (ARIN, RIPE NCC...), which allocate to ISPs and enterprises (often /32 to ISPs, /48 to sites). 2001:db8::/32 is reserved for documentation, which is why it fills every example.

Unique local (ULA), fc00::/7. The rough equivalent of RFC 1918: used inside a site or between cooperating sites, not routed on the Internet. RFC 4193 splits the space with the 8th bit (the L bit): L = 1 means locally assigned, giving fd00::/8, which is what everyone actually uses. The next 40 bits are a pseudo-random Global ID so that two companies that merge are unlikely to collide, then a 16-bit subnet ID and the 64-bit interface ID. Example: fd3c:9a1e:77b2:10::1/64. The old site-local range fec0::/10 is deprecated; if you see it in an answer, it is a distractor.

Link-local (LLA), fe80::/10. Valid only on one link; routers never forward packets with a link-local source or destination off the link. Every IPv6-enabled interface must have one, and it is created automatically (FE80::/64 plus an interface ID). Link-local addresses do real work:

  • A host's default gateway is the router's link-local address, learned from the RA.
  • NDP messages (RS, RA, NS, NA) are sourced from link-local addresses.
  • Routing protocols (OSPFv3, EIGRP for IPv6) form neighbors and use next hops that are link-local addresses, so show ipv6 route shows next hops like via FE80::2, GigabitEthernet0/0/2.

Exam trap: fe80::/10 technically covers fe80 through febf, but real link-local addresses always start fe80:0000:0000:0000. An answer like "FE90::1 is a global unicast address" is wrong (it is inside fe80::/10); an answer like "FF02::1 is link-local" is wrong (it is link-local scope multicast, not a link-local unicast address).

1.9.b Anycast

An anycast address is a unicast address assigned to more than one device. Routing delivers each packet to the nearest one (by routing metric). Nothing in the address format distinguishes anycast from unicast; you have to tell the device. Typical uses: DNS resolvers and root servers, CDN front ends, redundant services.

R1(config)#interface Loopback10
R1(config-if)#ipv6 address 2001:db8:acad:99::1/128 anycast
R2(config)#interface Loopback10
R2(config-if)#ipv6 address 2001:db8:acad:99::1/128 anycast

The anycast keyword tells IOS not to run Duplicate Address Detection on it (a duplicate is the whole point). IPv6 also defines a built-in anycast address on every subnet: the subnet-router anycast address, which is the prefix with an all-zeros interface ID (for 2001:db8:acad:10::/64 it is 2001:db8:acad:10::). It reaches any router on that subnet; this is one reason RFC 6164 has routers disable it on /127 links.

Solicited-node multicast derivation. Take the prefix ff02::1:ff00:0/104 and append the last 24 bits (the last 6 hex digits) of the unicast or anycast address.

  1. Address 2001:db8:acad:10:21a:2bff:fe3c:4d5e. Last 6 hex digits: 3c:4d5e. Solicited-node: ff02::1:ff3c:4d5e.
  2. Address 2001:db8:acad:10::1 (expanded ...:0000:0001). Last 6 hex digits: 00:0001. Solicited-node: ff02::1:ff00:1.
  3. Address 2001:db8:acad:20::25. Last 6 digits 00:0025, solicited-node ff02::1:ff00:25.

Why it matters: an NS for address resolution goes to this group, so it reaches only the target (and the rare host sharing those 24 bits). On Ethernet, IPv6 multicast maps to MAC 33:33 followed by the low 32 bits of the group, so ff02::1:ff3c:4d5e becomes MAC 3333.ff3c.4d5e and the NIC can filter it in hardware. That is a big improvement over ARP broadcasts, which interrupt every host.

1.9.d Modified EUI-64

Modified EUI-64 builds a 64-bit interface ID from a 48-bit MAC address. IOS uses it for automatic link-local addresses, for ipv6 address PREFIX/64 eui-64, and for SLAAC with ipv6 address autoconfig.

  1. Split the MAC in half: the 24-bit OUI and the 24-bit device part.
  2. Insert FFFE in the middle. Now you have 64 bits.
  3. Flip (invert) the 7th bit from the left of the first byte, the universal/local (U/L) bit. In hex this means XOR the first byte with 0x02: change the second hex digit by 2 (0 becomes 2, 2 becomes 0, 4 becomes 6, C becomes E, D becomes F and so on).
  4. Write the result as four hextets and prepend the /64 prefix.

Worked example 1. MAC 00:1A:2B:3C:4D:5E (Cisco format 001a.2b3c.4d5e).

  • Split and insert: 001A2B FFFE 3C4D5E
  • First byte 00 = 0000 0000, flip bit 7: 0000 0010 = 02
  • Interface ID: 021A:2BFF:FE3C:4D5E
  • With prefix 2001:db8:acad:10::/64: 2001:db8:acad:10:21a:2bff:fe3c:4d5e; link-local fe80::21a:2bff:fe3c:4d5e

Worked example 2. MAC 5C:A6:2D:11:22:33.

  • Split and insert: 5CA62D FFFE 112233
  • First byte 5C = 0101 1100, flip bit 7: 0101 1110 = 5E
  • Interface ID: 5EA6:2DFF:FE11:2233; link-local fe80::5ea6:2dff:fe11:2233

Worked example 3 (bit already set). MAC 02:00:5E:10:00:01.

  • Split and insert: 02005E FFFE 100001
  • First byte 02 = 0000 0010, flip bit 7: 0000 0000 = 00 (flip means invert, not "set")
  • Interface ID: 0000:5EFF:FE10:0001, compressed with prefix 2001:db8:acad:10::/64: 2001:db8:acad:10:0:5eff:fe10:1

Worked example 4 (your Proxmox VMs). Proxmox gives VM NICs MACs starting BC:24:11. MAC BC:24:11:5A:3C:7E: first byte BC = 1011 1100, flipped 1011 1110 = BE. Interface ID BE24:11FF:FE5A:3C7E, link-local fe80::be24:11ff:fe5a:3c7e. You can check this on a Debian VM in the 1.10 lab.

Worked example 5 (Cisco doc example). MAC 0060.3E47.1530 gives interface ID 0260:3EFF:FE47:1530, link-local FE80::260:3EFF:FE47:1530 and solicited-node FF02::1:FF47:1530.

Tip: Quick U/L flip table for the second hex digit: 0-2, 1-3, 4-6, 5-7, 8-A, 9-B, C-E, D-F (each pair swaps). Only the second hex digit of the first byte changes. And FFFE always lands in the middle: the 4th hextet starts with FE, the 3rd hextet ends with FF.

Exam trap: Distractors insert FFFE but forget the flip (001A:2BFF:FE3C:4D5E), flip the wrong bit (011A...), or insert FFFF. Also remember that EUI-64 only applies with a /64 prefix.

Unspecified and loopback

  • :: (unspecified, ::/128): all zeros. Used only as a source address when a host has no address yet, for example in the DAD Neighbor Solicitation. Never a destination.
  • ::1 (loopback, ::1/128): the equivalent of 127.0.0.1, but just one address. ping ::1 tests the local IPv6 stack.
  • ::/0 is not an address but the IPv6 default route (ipv6 route ::/0 ..., topic 3.3).

Recap

  • Global unicast 2000::/3 (starts 2 or 3); unique local fc00::/7 (fd in practice); link-local fe80::/10; multicast ff00::/8; no broadcast.
  • Link-local is automatic on every IPv6 interface, never routed, and used as the default gateway and routing next hop.
  • Anycast = same unicast address on several devices, nearest one wins; IOS keyword anycast, no DAD.
  • ff02::1 all nodes, ff02::2 all routers, ff02::5/6 OSPF, ff02::9 RIPng, ff02::a EIGRP, ff02::1:2 DHCPv6.
  • Solicited-node = ff02::1:ff + last 24 bits of the address.
  • Modified EUI-64: split MAC, insert FFFE, flip the 7th bit (XOR first byte with 02).
  • :: is unspecified (source only), ::1 is loopback, ::/0 is the default route.

1.11.a Nonoverlapping Wi-Fi channels

2.4 GHz. The band is only about 83.5 MHz wide (2.400 to 2.4835 GHz). Channels are numbered 1 to 14 with centers just 5 MHz apart (channel 1 = 2.412 GHz, channel 6 = 2.437 GHz, channel 11 = 2.462 GHz), but each transmission is about 20 to 22 MHz wide. So a channel overlaps the four on each side of it. In the US (FCC), channels 1 to 11 are allowed, and the only set of three channels that do not overlap is 1, 6 and 11. A cell design alternates these three so neighboring APs never share or straddle a channel.

5 GHz. Much more spectrum, and channels are spaced 20 MHz apart so adjacent 20 MHz channels do not overlap. The US has about 25 nonoverlapping 20 MHz channels in UNII-1 (36, 40, 44, 48), UNII-2 and UNII-2 Extended (52 to 64 and 100 to 144, shared with radar and so requiring Dynamic Frequency Selection, DFS) and UNII-3 (149 to 165). Exact availability varies by country and changes over time; the exam point is "5 GHz has many nonoverlapping channels, 2.4 GHz has three". Channels can be bonded: 40, 80 or 160 MHz wide, which multiplies throughput but divides the number of nonoverlapping channels (only a handful of 80 MHz and two or so 160 MHz channels in the US).

6 GHz. Opened in the US in 2020: 1,200 MHz from 5.925 to 7.125 GHz, 59 nonoverlapping 20 MHz channels (or 14 at 80 MHz, 7 at 160 MHz, and 320 MHz channels for Wi-Fi 7). Only Wi-Fi 6E and Wi-Fi 7 clients can use it, there are no legacy devices to slow it down, and WPA3 (or Enhanced Open/OWE) is mandatory.

Channel width trade-off. Wider channels mean higher peak rates per client but fewer channels to reuse, so more co-channel interference in dense deployments. Enterprise designs typically use 20 MHz in 2.4 GHz and 20 or 40 MHz in 5 GHz.

Exam trap: "Which three 2.4 GHz channels are nonoverlapping?" is 1, 6, 11 (not 1, 5, 9, 13 and not 1, 7, 13 for a US exam). 802.11a and 802.11ac never use 2.4 GHz.

1.11.b SSID and service sets

SSID (Service Set Identifier)
The human-readable network name, up to 32 bytes, case-sensitive. It is advertised in beacons (unless hidden; hiding it is not security, since it still appears in probe frames). Different SSIDs on one AP are usually mapped to different VLANs.
BSSID (Basic Service Set Identifier)
The MAC address of the AP radio serving a BSS. An AP broadcasting three SSIDs on two radios has six BSSIDs (each SSID gets its own virtual MAC per radio). The BSSID identifies the cell; the SSID identifies the network.
BSS (Basic Service Set)
One AP and its associated clients. The coverage area is the Basic Service Area (BSA), or cell. Clients talk through the AP, never directly to each other.
ESS (Extended Service Set)
Two or more BSSs with the same SSID, connected by a distribution system (DS), normally the wired switched network. Lets clients roam between APs while staying on the same network.
IBSS (Independent BSS, ad hoc)
Clients talk directly with no AP. Small, temporary, not used in enterprises.
Distribution system (DS)
The upstream (usually Ethernet) network the APs bridge wireless frames into.
Other topologies
Repeater (extends a cell by retransmitting), workgroup bridge (WGB, connects a wired device to the WLAN as a client), outdoor bridge (point-to-point or point-to-multipoint links between buildings), mesh (APs connect to each other wirelessly, with one root AP wired to the DS).

Roaming. The client, not the AP, decides when to roam: as the signal from its current AP weakens, it scans for a stronger BSSID with the same SSID and reassociates. For seamless roaming, neighboring cells should overlap by about 10 to 20 percent and use different nonoverlapping channels. With a WLC, the client keeps its IP address because the WLAN maps to the same VLAN everywhere (intra-controller roaming).

1.11.c RF fundamentals

Frequency
Cycles per second (Hz). Wi-Fi uses 2.4, 5 and 6 GHz.
Wavelength
Distance of one cycle; inversely proportional to frequency (speed of light / frequency). About 12.5 cm at 2.4 GHz and 6 cm at 5 GHz. Longer waves travel farther and penetrate obstacles better, so 2.4 GHz covers more area than 5 or 6 GHz at the same power.
Amplitude
The strength (height) of the wave; what you measure as signal power.
Phase
The position of a wave in its cycle. Modulation schemes (QAM) encode data in amplitude and phase.

Power units. Watts and milliwatts are absolute; decibels are logarithmic ratios.

  • dBm is power relative to 1 mW: 0 dBm = 1 mW, 10 dBm = 10 mW, 20 dBm = 100 mW, 30 dBm = 1 W.
  • Rule of 3s and 10s: +3 dB doubles power, -3 dB halves it; +10 dB multiplies it by 10, -10 dB divides by 10. So 100 mW (20 dBm) minus 3 dB = 50 mW (17 dBm); 1 mW minus 10 dB = 0.1 mW (-10 dBm).
  • dBi is antenna gain relative to an isotropic antenna. EIRP = transmitter power (dBm) - cable loss (dB) + antenna gain (dBi). Example: 20 dBm - 3 dB + 6 dBi = 23 dBm EIRP.
RSSI (Received Signal Strength Indicator)
How strong the received signal is, shown in dBm as a negative number. Closer to zero is stronger: -45 dBm is excellent, -67 dBm is a common minimum design target for voice and real-time apps, around -80 dBm is unusable for most clients. (Strictly, RSSI is a vendor-defined index, but Cisco and most tools report it in dBm.)
Noise floor
Background RF energy on the channel, typically around -90 to -95 dBm.
SNR (Signal-to-Noise Ratio)
Signal minus noise floor, in dB. -65 dBm signal with a -92 dBm noise floor gives SNR 27 dB. Higher SNR allows higher data rates (denser modulation); about 25 dB or more is a good target.

Interference.

  • Co-channel interference (CCI): two APs on the same channel hear each other. They do not corrupt each other's frames so much as share the airtime, because CSMA/CA makes them take turns. Fix: channel plan with 1/6/11, lower power, more 5 GHz.
  • Adjacent-channel interference (ACI): APs on overlapping channels (for example 1 and 3). This is worse: the energy corrupts frames instead of being detected and deferred to. Fix: only use nonoverlapping channels.
  • Non-Wi-Fi interference: microwave ovens (2.4 GHz), Bluetooth, cordless phones, wireless cameras, radar (5 GHz DFS channels).

Half-duplex and CSMA/CA. A radio cannot transmit and receive on the same channel at once, and all devices in a cell share one channel, so Wi-Fi is half-duplex, like a hub. Collisions cannot be detected while transmitting, so 802.11 avoids them instead (Carrier Sense Multiple Access with Collision Avoidance):

  1. Listen: is the channel idle (physical carrier sense, plus the virtual Network Allocation Vector set by other frames' duration fields)?
  2. If idle, wait a fixed interframe space (DIFS) plus a random backoff; if still idle, transmit.
  3. The receiver sends an ACK for every unicast frame. No ACK means the sender assumes a collision and retries with a longer random backoff.
  4. Optional RTS/CTS reserves the medium first, which helps with the hidden node problem (two clients that both hear the AP but not each other).

1.12 Explain virtualization fundamentals (server virtualization, containers and VRFs)

Virtualization means one physical thing presenting itself as several logical ones. The CCNA covers three forms: server virtualization (many virtual machines on one host), containers (many isolated applications on one OS kernel) and VRFs (many routing tables on one router). You run the first two every day on your Proxmox box, which makes this topic mostly about naming things precisely.

Server virtualization and hypervisors

A virtual machine (VM) is a software computer with its own virtual CPU, memory, disk and NICs, running its own full operating system (the guest OS). The hypervisor (virtual machine monitor) creates VMs and shares the physical hardware among them, isolating each one.

Type 1 (bare metal, native)Type 2 (hosted)

UseData centers and production serversDesktops and laptops: labs, testing, running another OS
OverheadLower; direct hardware accessHigher; goes through the host OS

Your homelab is a type 1 example: Proxmox VE installs on bare metal and runs VMs with KVM (and containers with LXC). If you ran VirtualBox on the same laptop under Windows instead, that would be type 2.

Benefits the exam likes: higher hardware utilization (consolidation), faster provisioning (deploy from templates), snapshots and easy backup/restore, live migration between hosts (vMotion), isolation between workloads, and lower power, cooling and rack space.

Virtual networking: vNICs and virtual switches

Each VM has one or more virtual NICs (vNICs) with their own MAC addresses. vNICs plug into a virtual switch inside the hypervisor, which behaves like a Layer 2 switch: it learns MACs and forwards frames between VMs on the same host without touching the physical network. The host's physical NICs act as the virtual switch's uplinks to the physical access switch. Virtual switches support VLANs, so the uplink to the physical switch is usually an 802.1Q trunk carrying all the VMs' VLANs.

  • VMware: vSwitch (standard) and vSphere Distributed Switch; Hyper-V: Hyper-V virtual switch; Proxmox/KVM: Linux bridge (the installer creates vmbr0 bridged to the first NIC) or Open vSwitch.
  • Traffic between two VMs on the same host and VLAN never leaves the server, so the physical network (and its monitoring) never sees it.

Containers

A container packages an application with its libraries and dependencies and runs it as an isolated process on the host OS. All containers on a host share the host's OS kernel; there is no guest OS per container.

Docker is the best-known container engine: an image is a read-only template (built from a Dockerfile), a container is a running instance of an image, and a registry (such as Docker Hub) stores images. Kubernetes is a container orchestrator: it schedules containers across a cluster of hosts, restarts failed ones (self-healing), scales them, load-balances traffic to them and handles rolling updates. For the CCNA, know that containers are lightweight and share a kernel, Docker runs them, and Kubernetes orchestrates them at scale. Containers are a natural fit for microservices.

VRFs (Virtual Routing and Forwarding)

A VRF is a separate routing table (and forwarding table, CEF FIB) inside one router or Layer 3 switch. Each routed interface belongs to exactly one VRF (or to the global table, which is what you use when you configure no VRF). Packets that arrive on an interface in VRF CUST-A are routed only with CUST-A's table and can only leave through CUST-A interfaces. The result is one physical router acting like several independent routers.

  • Overlapping addresses are allowed between VRFs: CUST-A and CUST-B can both use 10.1.1.0/24 on the same router, because the routes live in different tables.
  • Path isolation: guest, corporate and OT/lab traffic can share hardware while staying separate at Layer 3, the way VLANs separate traffic at Layer 2. This is useful anywhere regulated systems (like GxP lab networks) must be kept apart from corporate traffic.
  • VRF-lite is VRFs used without MPLS. Service providers use VRFs with MPLS and MP-BGP to build MPLS Layer 3 VPNs; that part is beyond the CCNA.

1.13 Describe switching concepts

A Layer 2 switch forwards Ethernet frames based on destination MAC addresses, using a table it builds itself by watching source MAC addresses. Four behaviors define it: learn, forward, filter and flood. Everything later (VLANs, STP, port security) builds on these.

1.13.a MAC learning and aging

Learning. For every frame received, the switch reads the source MAC address and records it in the MAC address table (also called the CAM table) with the ingress port and VLAN. Switches never learn from destination addresses. Source MACs are always unicast, so broadcast and multicast addresses are never learned dynamically.

  • If the MAC is new, the switch adds an entry.
  • If the MAC is already there on the same port, the switch refreshes the entry's age timer.
  • If the MAC shows up on a different port (a device moved, or a loop), the switch updates the entry to the new port.

Aging. Dynamic entries that are not refreshed are removed after the aging time, 300 seconds (5 minutes) by default on Catalyst switches. This keeps the table current when devices move or disappear and frees space. Change it globally or per VLAN with mac address-table aging-time (10 to 1,000,000 seconds; 0 disables aging). Static entries never age.

SW1(config)#mac address-table aging-time 600
SW1(config)#mac address-table aging-time 120 vlan 20
SW1(config)#mac address-table static 0050.7966.6804 vlan 20 interface GigabitEthernet1/0/4

SW1#show mac address-table aging-time
Global Aging Time:  600
Vlan    Aging Time
----    ----------
  20     120

Older IOS versions spelled the command mac-address-table with a hyphen; current IOS and IOS XE use mac address-table.

1.13.b Frame switching (forwarding and filtering)

For each frame, the switch looks up the destination MAC in the table for the frame's VLAN:

DestinationDecision
Known unicast, on a different portForward out that one port only.
Known unicast, on the same port the frame arrived onFilter (drop): the destination is already on that segment (for example behind a hub).
Unknown unicast (not in the table)Flood out all ports in the VLAN except the ingress port.
Broadcast (ffff.ffff.ffff)Flood out all ports in the VLAN except the ingress port.
MulticastFlood in the VLAN, unless IGMP snooping has learned which ports want the group.

Flooding and forwarding are always confined to the frame's VLAN. Trunks carry the frame to other switches, which repeat the same logic.

Switching methods (how much of the frame is received before forwarding):

  • Store-and-forward: receives the whole frame and checks the FCS (CRC) before forwarding; discards corrupted frames. Highest latency, but the default on Catalyst switches and required when speeds differ between ports.
  • Cut-through: starts forwarding as soon as it has read the destination MAC (first 6 bytes after the preamble). Lowest latency, but forwards frames with bad FCS. Used in some low-latency data center switches.
  • Fragment-free: a cut-through variant that waits for the first 64 bytes (the collision window) so it does not forward collision fragments (runts).

1.13.c Frame flooding

Flooding is normal: it is how a switch delivers a frame before it knows where the destination is, and how broadcasts such as ARP requests and DHCP Discovers reach every host. Typically the first frame to an unknown host is flooded, the destination replies, the switch learns the reply's source MAC, and from then on frames are forwarded out one port.

Exam trap: When the MAC table fills up (for example in a MAC flooding attack that sends thousands of fake source MACs), new destinations cannot be learned and are flooded, so the switch effectively acts like a hub for that traffic and an attacker can capture it. Port security (5.7) limits the number of MACs per port to stop this.

Collision domains and broadcast domains

  • Collision domain: devices whose transmissions can collide. A hub (Layer 1) puts all its ports in one collision domain. Every switch port is its own collision domain, and in full duplex no collisions occur at all.
  • Broadcast domain: devices that receive each other's broadcasts. A switch floods broadcasts, so each VLAN is one broadcast domain. A router does not forward broadcasts, so each router interface (or subinterface/SVI) bounds a broadcast domain.

Counting example. R1 G0/0 connects to SW1, which has three PCs. R1 G0/1 connects to SW2, which has two PCs on two ports and a hub on a third port with three PCs behind it. All switch ports are in VLAN 1.

  • Broadcast domains: 2 (one per router interface).
  • Collision domains: SW1 has 4 (three PC ports plus the router link). SW2 has 4 (router link, two PC ports, and the hub port; the hub and its three PCs share one collision domain). Total 8.

Remember: Hubs: one collision domain, one broadcast domain. Switches: one collision domain per port, one broadcast domain per VLAN. Routers: one broadcast domain per interface.

Recap

  • Switches learn source MAC + port + VLAN; dynamic entries age out after 300 seconds by default (mac address-table aging-time); static entries never age.
  • Known unicast: forward out one port (filter if it is the ingress port). Unknown unicast, broadcast, multicast: flood within the VLAN except the ingress port.
  • show mac address-table [dynamic | vlan | interface | address | count]; clear mac address-table dynamic.
  • Store-and-forward checks FCS (Catalyst default); cut-through forwards after the destination MAC; fragment-free after 64 bytes.
  • Each switch port is a collision domain; each VLAN (router interface) is a broadcast domain; a hub is one collision domain.
